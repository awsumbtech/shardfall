# Shardfall vs Brian's OO definition (Nov 15)

Bar (Brian, Nov 15): he must be able to change or add any foe, NPC, item, backdrop, or effect, or switch the whole theme, only by updating or adding art files and data entries, with no code edits.

This pass is a gap audit against that bar, with file:line evidence, on the OO-04 / v0.4.37 tree. It is not a claim that step 2c finished the conversion.

## Summary

- The game is not at that bar overall. Stats and encounter rows already live in `js/data/*`, but adding or reskinning a foe, NPC, item, or effect, or switching the theme, still requires a code edit in almost every case. Battle backdrops now meet the bar: a new area is a row in `js/data/battle-backdrops.js` plus art files, with no object or `sw.js` edit. Step 2c has four areas marked ready (emberhold_meadow, emberhold_scar, cinderveil_ash, ember_vault); the other four stay on today's path until their rows and plates land.
- Hard-coded type lists still sit next to the data files. `SF.KIND_SPRITE` (`js/draw/actors.js:335-343`) maps field kinds to sprite ids. `BattleGfx` keeps closed `COL`, `BG`, `UNIT_SHORT`, and `UNIT_TIGHT` maps (`js/battle/gfx.js:7-34`, `:337-365`) and a `sourceSize` if-chain on sprite ids (`:124-126`). Battle backdrop ids are no longer in that set: `BattleBackdrop.IDS`, ready flags, layer paths, parallax, z, and horizon now come from `js/data/battle-backdrops.js`, and `BattleBackdrop.adopt()` is the only reader. An unknown id falls back to `defaultId` in that file.
- Switch / if chains on ids and kinds are still the dispatch. Field painters branch on kind (`js/draw/actors.js:353-357`, `:365`, `:387`, `:435`; `js/grapple.js:333-359`). Item icons are inferred from slot and flags, then drawn by `kind === "bottle"` / `"flask"` / … (`js/world.js:1334-1400`). Element bursts pick a rect shape per element (`js/battle/stage.js:497-503`). `sim.js` and `battle.js` special-case `maw`, `tidewyrm`, `brumekin`, and `choirling` (`js/sim.js:290`, `:297`, `:328`, `:1022`, `:1123-1145`; `js/battle/battle.js:432-464`, `:568`).
- Code-drawn art is still the default look. The palette-indexed engine and per-id painters live in `js/art/*` (`js/art/core.js:8-116`, `js/art/actors.js` `eBind` / `ePortrait` around `:2196-2237`). Unready battle areas still use `Art.battleBg` / `BattleGfx.paintBg` (S14, `js/battle/gfx.js:62-91`). Title, voyage, field sky, props, pickups, and DOM chrome remain primitives (Part A of `docs/OO-MIGRATION.md`).
- Per-type code paths go beyond drawing. Field AI and tells branch on kind; Cinder Maw and Tidewyrm have dedicated hooks. A new foe with its own behavior still needs a `sim.js` / `grapple.js` edit even after a data row exists. Steps 17-19 and 26 extract those objects; they do not make a new type data-only.
- Palettes and theme values live in code, not in a skin file. `Art.HEX` / `Art.C` (`js/art/core.js:8-116`), battle unit and backdrop color tables (`js/battle/gfx.js:7-34`), element FX (`js/battle/stage.js:478-482`), item-icon hexes (`js/world.js:1343-1400`), CSS `:root` tokens (`css/style.css:1-16`), and the sky-gradient fallback (`js/draw/sky.js:11`) all have to be edited to reskin the game. There is no `SF.SKY` data table; the fallback stops in `draw/sky.js` are the theme.
- Foes: `SF.FOES` / `SF.ENCOUNTERS` / `SF.KINDS` (`js/data/enemies.js:7`, `js/data/encounters.js:7`, `js/data.js` `SF.KINDS`) can take a new row, but a visible new foe also needs a painter or sheet bind, a `KIND_SPRITE` entry, BattleGfx color / name / size, and often a field draw or AI branch (steps 18, 26; battle sheets can later hang off a `BattleFoeSprite` without steps 17/10). Data alone is not enough.
- NPCs and items: `SF.NPCS` (`js/data.js:91`) is a position list. Field fallbacks and portraits are per-id painters (`js/draw/actors.js:158-314`; `js/art/actors.js` around `:865`; `js/dialogue.js:901`). Item stats in `js/data/items.js:13` do not carry an icon path; `SF.paintLootIcon` invents and code-draws one (step 24 / U16).
- Backdrops and effects: emberhold_meadow, emberhold_scar, cinderveil_ash, and ember_vault are art + a ready flag in `js/data/battle-backdrops.js` (step 2c). A new battle area is a data-file row plus art; `sw.js` `importScripts` that catalog and precaches `data.precache`, so it needs no edit. The other four areas are still unready and stay on today's code-drawn path until their rows are marked ready and their plates land. Field sky, title, voyage, particles, hit flashes, slashes, glows, and element bursts remain code-drawn (steps 6, 13, 19, 25, 36, 37).
- Uncovered by any OO-MIGRATION step: a real theme / skin data file; making foe / NPC / item / effect registries accept a new id with a sheet path and no painter, color map, or kind switch. The battle-backdrop catalog + precache gap is closed in this PR: a new area is art + a `js/data/battle-backdrops.js` entry only.
