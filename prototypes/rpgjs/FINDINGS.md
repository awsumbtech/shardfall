# RPG-JS v5 spike: Emberhold

Prototype only. Do not merge. Do not deploy.

Branch `spike/rpgjs-emberhold`. Packages tried: `@rpgjs/client` 5.4.0, `@rpgjs/server` 5.3.0, `@rpgjs/common` 5.2.0, `@rpgjs/tiledmap` 5.0.2, `@rpgjs/ui-css` 5.3.0, `@rpgjs/vite` 5.0.4, `@canvasengine/tiled` 2.4.1, `canvasengine` 2.5.2, `pixi.js` 8.22.0, Vite 8.3.7. The loader notes below are from `loader-report.json`, generated by `node tools/probe-loader.mjs` against those installs.

The running scene is `src/tiled/emberhold.tmx`, produced from a copy of `js/content/maps/emberhold.tmj`. `emberhold-full.tmx` is the faithful conversion and is what the probe compares to the tmj. Both are generated by `tools/convert-tmj.mjs` and are not committed.

## What carried over

- Finite orthogonal map, 170×112, 16px tiles. The parser kept width, height, tile size, map properties (`island`, `private`), and all 39 layers on the full TMX.
- GID sums matched the tmj once CSV line breaks were written with a comma before the newline. The XML parser deletes a bare newline and glues two gids into one number.
- Point objects survived. `maren` is still a point at 1088, 288, type `npc`. Zones and edge-inset properties survived on top-level object layers.
- The meta tileset's tile types survived: `blocked`, `h0`, `h1`, `h2`, `h3`, `stair`.
- `art/fx-tiles.png` and `art/meta-tiles.png` are the only tile images in the repo. They load. The other 16 tilesets 404.
- Arrow keys move the client sprite one tile per press. Built-in mobile controls (stick, A, B, and a dash button labeled R here) draw in both 844×390 and 390×844.
- `showText` / `showChoices` can show the RPG-JS dialog. Maren's three TEMP choices render. Choosing "Keep this place" calls `player.save(0)`.
- `LocalStorageSaveStorageStrategy` wrote slot 0 under `shardfall-rpgjs-spike`. Load does not draw the Wayfarer. Both runs saved client (1083, 304). The client then walked to y 366 (dy 62) and stayed at y 366 after load. The 112px sprite is still in the Pixi list, graphic `wayfarer`, and its bounds overlap the viewport (landscape 402,166 56×56; portrait 175,337 56×56), but the sprite or an ancestor is hidden, so `drawn` is false. The save/load PNGs show Maren only. Server y went 304 at save, 320 while away, and back to 304 after Load, so Load reset the server player while the client sprite did not move and was not drawn. Numbers: `prototypes/rpgjs/evidence/capture-log.json`.

## What broke

- The tmj is rejected. `@canvasengine/tiled` 2.4.1 parses XML only. Feeding the JSON throws `Text data outside of root node` at the closing `}`.
- `@rpgjs/tiledmap` fetches `` `${basePath}/${map}.tmx` `` and then each `tileset.source`. There is no `.tmj` path. An embedded tileset (what our tmj uses) has `source: null`, so that fetch cannot run.
- Custom property `role` is dropped on all 28 tile layers that live inside the sibling groups `level-0` through `overlay`. Top-level layers keep their properties. The parser walks one group object; several sibling groups become an array and the children are not indexed, so the compact property bag is never applied. Tile numbers still parse.
- Collision is not our collision layer. RPG-JS blocks a tile only when the tile property `collision` is true. Our collision layer is a grid of meta and kenmi-grass gids. None of those tiles set `collision`. Height is `z` on the layer plus `z` on the tile, in pixels of `zTileHeight`. Our height layer is meta tiles `h0`–`h3` and `stair`. Those types are kept as tile types and are not applied as height.
- The client tile component (`CompositeTileLayer.onUpdate` in `@canvasengine/presets` 2.6.0) rebuilds every nonzero cell on every frame and does not read `layer.visible`. The invisible collision, paths, and height layers are about 17,000 meta tiles. Left in the running map, that repaint dominates. The running TMX therefore omits those layers and every Kenmi gid. The full file still has them.
- Loading the full TMX in the browser requests `map/images/missing/kenmi-grass.png`, gets a 404, and Pixi's loader throws. The tileset loop is a chain of `await`. The first failure never reaches `layers.set`, so the event layer never mounts. The canvas stays black, keyboard controls never attach, and the player coordinates exist only on the server object. Screenshot: `prototypes/rpgjs/evidence/landscape_844x390_full_map_missing_kenmi.png` (the capture swaps in `emberhold-full.tmx` for this shot only; see `tools/capture.mjs` L308-337).
- With Kenmi gids cleared, the view at Maren is still empty. Every visible ground tile on Emberhold is a Kenmi sheet. The only in-repo visible pixels are 38 `kenmi-fx` cells on `L1/footfx`, and none of them are near the start. Meta tiles would paint the island mask, and the renderer would draw them even though those layers are hidden, but the running map leaves them out because of the per-frame rebuild.
- Client sprite position and server `player.x()` / `player.y()` diverge. Arrow keys move the client sprite (320 → 304, one tile up into Maren). The server value stays at the spawn until `teleport` or `load`. `moveTo` throws `Cannot read properties of undefined (reading 'getStrategies')` because the server room object has no `moveManager`.
- `player.emit("gui.open")` did not arrive on the client socket, so `showText` waited forever with no box. `src/gui-bridge.ts` forwards `gui.open` / `gui.exit` to `guiService.display`. With that bridge, the dialog and the three choices render. A click on a choice did reach the server handler.
- Closing a second confirmation dialog did not reach the server, left `canMove` false, and the live variable display snapped back even though the localStorage slot was intact. The event therefore does not open a follow-up line after save or load. The readout carries the `saved` / `loaded` note.
- `Maximum call stack size exceeded` shows up intermittently while the GUI and camera start. The page usually keeps running afterward.
- Headless Chrome's Space key did not fire the action control. `engine.processAction({ action: "action" })` did, which is the same control as the on-screen A button. Enter advances the first line to the choices.

## How faithful the tmj was

The full TMX is the same map with a mechanical XML encoding: external tilesets, CSV tile data, groups, object points, and properties. After the comma-newline fix, the only fidelity diffs are the 28 dropped `role` properties. GIDs, visibility flags, object names, and the maren point match.

The running TMX is a smaller file (about 53KB against 1.3MB) because Kenmi gids are zero and empty or invisible layers are omitted. That is an adaptation so the scene can mount. It is not a claim that RPG-JS displayed Emberhold's ground.

## Sprite sheets

The PixelDoll sheets from commit `7457f94` are wired in `src/sprites.ts`. Scale is `0.5` on both. The south stand's opaque body is 30×63 inside the 112 cell, so half scale draws it at 15×31.5 px: about one 16px tile wide and two tiles tall. Maren uses the same scale, so her 45×62 opaque stand is about 22×31 px.

`wayfarer-outfitB.png` is 896×448, eight 112×112 frames across and four rows. Rows are S, E, N, W, mapped to `Direction.Down`, `Right`, `Up`, `Left`. Stand is frame 0 of the facing row. Walk is all eight frames of that row, 8 ticks apart. The foot anchor is `(56, 90)` in the cell, as a ratio `[0.5, 90/112]`. The opaque sole of the south stand is y=89. Centering the 80×80 body pivot `(40, 75)` in the cell lands on `(56, 91)`. The handoff's "~101" sits below the pixels, so the anchor uses the measured sole. `x: 8, y: 16` puts that anchor on the bottom center of the 16×16 hitbox.

`npc-maren.png` is one 80×80 south-facing stand. `framesWidth` and `framesHeight` are both 1. Stand and walk both play that single frame, so she does not turn. Her foot is `(39, 74)`.

RPG-JS does not take a list of named rects. `framesWidth` / `framesHeight` are the column and row counts, and `rectWidth` / `rectHeight` are the cell. `textures.stand` and `textures.walk` are functions of `{ direction }` that return a timeline of `{ time, frameX, frameY }`. `scale` and `anchor` are arrays on the sheet; a bare number cannot be spread into `sprite.scale.set`. An 8-frame row works. The engine does not know the letters S/E/N/W, and it does not mirror a row: west is its own row of eight frames.

A `footAnchor` field on each frame is rewritten into a new object on every animation pass and overflowed the signal stack, so the spike does not use it.

`js/assets/sheet.js` is a different job. It stores one image and a grid or a list of named rectangles (`r0c0`, or clip names). The caller asks for a frame by name or index. It does not play a direction timeline, does not own stand versus walk, and does not place a foot anchor. Our field animator does that outside the sheet. RPG-JS folds the timeline, the direction, the scale, and the anchor into the sheet object.

Art, not the engine: the south walk's legs barely change across the eight frames, and the west row is a mirror of the east row, so the staff swaps hands. The engine plays those frames as they are.

The running map still drops the 16 missing Kenmi tilesets, so a 404 cannot abort the scene. It also marks the markers object layer visible. RPG-JS parents the sprites to each object layer and hides that layer when Tiled marks it invisible. With markers visible, the Wayfarer and Maren both draw on the empty ground.

## Event scripting

`src/modules/main/event.ts` is an RPG-JS `EventDefinition`: `onInit` sets a 16×16 hitbox, `onAction` runs `showText` then `showChoices`. Lines are TEMP and tone-neutral. The real lines stay with the Shardfall Script bot.

The maren point can auto-place an event with no `x`/`y`, and the parser does see that point. In the browser the client scene's event list stayed empty until the event was also given `x: 1088, y: 288`. The spike sets both.

## Mobile controls

`withMobile({ enabled: "always", buttons: { action: true, back: true, dash: true } })`. `"always"` is so a desktop browser shows the same overlay a phone would. Production would use `"auto"`. The stick and buttons are the engine's, drawn as DOM over the canvas. They are on screen at 844×390 and at 390×844. Movement from the arrow keys is cardinal and one step per press in this scene. The stick was not driven in the automated pass. The A button and `processAction({ action: "action" })` share a control. Space did not open the dialog in headless Chrome.

## Battle stays ours

`js/battle/*` was not imported. `SF.Battle.start(encounterId, opts)` in `js/battle/battle.js` needs `SF.state`, builds the battle object, sets `s.mode = "battle"`, and returns. The field loop draws it. `@rpgjs/action-battle` is a different, real-time system and was not installed.

A plug-in that keeps our battle:

1. Event hook. An RPG-JS `onPlayerTouch` or `onAction` builds a plain handoff: encounter id, party vitals, flags, rng seed. It does not call action-battle.
2. Scene or GUI overlay. A client GUI mounts the existing battle canvas over the map and sets `player.canMove = false`, the same lock the dialog uses. On the result it closes.
3. State handoff. The server player keeps the few numbers the field needs afterward (hp, position, quest flags via `setVariable`). An adapter constructs the `SF.state` slice `Battle.start` already expects, runs the current modules, and writes the result back. The battle scripts stay vanilla JS.

## Full migration versus borrowing

Full migration is a rewrite of the field. Emberhold's picture does not come across without the private atlas, and even with the atlas the height, stairs, collision layer, dash, hook, and grapple are not the RPG-JS model. Battle would stay an overlay. The site would gain a Vite and pnpm build, a ~828 KB gzip engine, and a server-shaped player inside the page. Effort: large. Risk: high for movement and height. Confidence: medium. This spike covered Emberhold's map, one NPC, save, and mobile controls, not Cinderveil or the hook.

Borrow only where the spike actually earned it:

| Piece | Effort | Risk | Take |
| --- | --- | --- | --- |
| Tiled loader (`@rpgjs/tiledmap` / `@canvasengine/tiled`) | large | high | Leave it. `js/tiles/tmjmap.js` already reads this tmj, including collision, height, and stairs. Their loader wants TMX, external TSX, a `collision` property, and `z`. |
| Sprite-sheet system | small for a direction timeline, large to adopt the renderer | low for the idea, high for the Pixi dependency | Their API did take the 112px cell and the 8-frame rows, once `framesWidth` was the column count and `rectWidth` was 112. `js/assets/sheet.js` still fits our named clips better. The weak south legs and the west staff swap are in the PNG. |
| Event scripting (`showText` / `showChoices` and the dialog box) | medium to lift the dialog, large to move `js/dialogue.js` onto their events | medium | The dialog is the part worth a second look. The socket bridge, the stack overflow, and the stuck `canMove` are the cost. |
| Save / load slots | small to sit beside `shardfall.v1`, medium to replace it | medium | The slot write worked. After load the 112px Wayfarer sprite is still in the display list, the sprite or an ancestor is hidden, and the PNG shows only Maren. Client y stays at the walked-away spot. Server y went 304, 320, then back to 304 after Load. The snapshot is not our save document. |

Confidence: high on the loader measurements (the probe and the 404 are repeatable), high that this run's load leaves the Wayfarer undrawn (the display-list assert fails and the save/load PNGs show Maren only), medium on the dialog once the bridge is in, medium on the migration size.
